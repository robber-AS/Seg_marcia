# GRUPO 1 — LANDING PAGE E CADASTRO DE VISITANTES

## 1. OBJETIVO

Crie uma aplicação web responsiva para a Landing Page de um evento escolar.

Esta aplicação será o **Grupo 1** de um sistema maior de eventos composto por quatro aplicações independentes:

1. Landing Page e Cadastro
2. Credenciamento
3. Leitor de QR Code
4. Dashboard

IMPORTANTE:

* Este projeto é SOMENTE o Grupo 1.
* Não criar telas de credenciamento.
* Não criar leitor de QR Code.
* Não criar dashboard administrativo.
* Não criar gerenciamento de grupos.
* Não criar telas para visualizar visitantes cadastrados.
* Não permitir que visitantes consultem dados de outros visitantes.
* O projeto utiliza o mesmo banco Supabase dos demais projetos.
* O acesso aos dados deve respeitar rigorosamente o RLS existente no Supabase.

Somente eventos com:

# 8. FORMULÁRIO DE INSCRIÇÃO

Criar formulário com os campos:

### Nome completo

Campo obrigatório.

Regras:

* mínimo de 3 caracteres
* remover espaços desnecessários
* não aceitar nome vazio

### CPF

Campo obrigatório.

Exibir máscara:

000.000.000-00

Internamente salvar somente números.

Exemplo:

Entrada:

123.456.789-09

Banco:

12345678909

### E-mail

Campo obrigatório.

Validar formato de e-mail.

### Telefone

Campo opcional.

Utilizar máscara apropriada para telefone brasileiro.

### Cidade

Campo opcional.

---

# 9. VALIDAÇÃO DE CPF

Implementar validação real do CPF no frontend.

O CPF deve:

* possuir 11 dígitos
* passar pela validação dos dígitos verificadores
* rejeitar sequências inválidas como:

00000000000
11111111111
22222222222
33333333333
44444444444
55555555555
66666666666
77777777777
88888888888
99999999999

Mostrar mensagem amigável:

"Digite um CPF válido."

Não enviar CPF inválido para o Supabase.

# 10. CADASTRO NO SUPABASE

Para realizar o cadastro, utilizar preferencialmente a função existente:

public.cadastrar_visitante

Parâmetros:

p_evento_id
p_nome
p_cpf
p_email
p_telefone
p_cidade

Não fazer INSERT direto na tabela visitantes se a função estiver disponível.

Utilizar a função RPC do Supabase.

Exemplo conceitual:

supabase.rpc("cadastrar_visitante", {
p_evento_id: eventoId,
p_nome: nome,
p_cpf: cpf,
p_email: email,
p_telefone: telefone,
p_cidade: cidade
})

---

# 11. CPF DUPLICADO

O banco já possui uma restrição:

unique(evento_id, cpf)

Portanto, se o CPF já estiver cadastrado no mesmo evento, não criar outro cadastro.

Mostrar mensagem:

"Este CPF já está cadastrado para este evento."

Não mostrar dados do visitante já cadastrado.

Não permitir consulta de dados existentes.
